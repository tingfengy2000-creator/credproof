1. 启动与停止

步骤操作
解压把压缩包完整解压到任意目录（中文和空格路径都可以）。不要只拷贝启动文件。
启动双击 密证CredProof.exe。会出现一个黑色窗口显示运行信息，几秒后默认浏览器自动打开工作台。也可以双击 start-credproof.cmd，效果完全相同。
首次运行提示如果出现“Windows 已保护你的电脑”，点“更多信息”→“仍要运行”。这是系统对未签名程序的常规提示；也可改用 start-credproof.cmd。
浏览器没有自动打开黑色窗口里会打印实际地址（如 http://127.0.0.1:8765），复制到浏览器打开即可；端口被占用时程序会自动换一个。
停止在黑色窗口中按 Ctrl+C，或直接关闭该窗口。演示中产生的临时数据会自动清理。
macOS / Linux需要 Python ≥ 3.11，在解压目录运行 sh start-credproof.sh。

默认启动的是查看模式：可以浏览所有真实记录、接入项目、填写配置、修订代码、记录决定，但不会在您的电脑上执行被测代码。需要现场跑检查时，见第 10 节。

3. 界面总览

  • 左侧导航分两组。“工作台”是可操作的功能：首页、我的项目、新建检查、复检导出包、运行环境。“参考材料”是只读的真实记录：对照与接入、对照评测、补丁记录、流水线闸门、案例回放、命令行接入、工作原理。
  • 右上角三个标签：第一个说明能否运行检查（查看模式显示不能，隔离验收模式显示“可以检查：隔离环境就绪”）；第二个是当前启动模式；第三个表示本机服务是否连接。
  • 页面只监听本机地址 127.0.0.1，所有数据都保存在解压目录内。

4. 首页：一个真实案例

首页用“资料助手”这个小工具讲完整流程：它按请求读取一份资料，再带着凭据调用一个服务。六步分别是：原问题 → AI 候选及遗漏 → 开发者修订 → 安全与业务验收 → 待人工采纳 → 导出复检。点页面上方的 1–6 可直接跳到对应步骤。

第 4 步：选一个版本，看五个问题

点击三个按钮“原问题 / AI 候选 v000 / 开发者修订 v001”切换版本。每个问题右侧的小标签会同时显示三个版本的状态，便于对比：原问题是“越界、外流”，AI 候选是“没有发生”，开发者修订是“正常”。

第 5 步：批准的是哪一份？

右侧按钮模拟“没有变化 / 改了代码 / 改了配置 / 换了访问组件 / 删了必要测试”。点任意一个变化，下方表格会标出哪一项不再一致，并说明此时旧批准失效、服务端会拒绝过期页面的提交（HTTP 409）。

第 6 步说明导出包如何在新目录重新执行完整检查。页面底部的“常见质疑”回答了“为什么不用现有 CI 或扫描器”“AI 有什么作用”等问题，“我们做了什么，哪些来自别处”列出了团队实现的部分与第三方组件。

5. 新建检查：接入一个项目

  1. 选择项目。三种方式任选：点“选择项目文件夹”选整个项目目录（页面会在浏览器里打包后上传）；点“选择 zip 文件”；或在右侧示例中点“使用”。示例包括首页案例“资料助手（问题版本）”和 8 个对照评测目标。上传上限 16 MiB、2000 个文件、单个文件 4 MiB，自动忽略 .git、虚拟环境和缓存；系统只做静态解析，不执行上传的代码。
  2. 填写检查配置。系统自动识别入口函数、必要测试目录和凭据环境变量并预填。逐项核对：
    • 入口：被检查的函数（如 tool.run）；
    • 必要业务测试：每行一个测试路径，这些测试必须全部执行并通过；
    • 文件与服务边界：允许目录（如 data）、禁止目录（如 secrets）、是否必须读取允许资料、允许的服务路径前缀、是否必须带凭据认证、凭据环境变量名；
    • 入口场景：每个场景用一个 JSON 请求调用一次入口，可用占位符代表允许文件、禁止文件、跳转地址等，也可声明预期异常和“必须发出网络请求”。下方快捷按钮可一键添加常用场景。
  3. 校验并开始。点“校验配置”，右侧“校验结果”显示“配置有效，可以开始”后，点“冻结配置并开始”。系统建立第 0 版（v000）并进入项目页。

6. 项目页：读结论、改代码、做决定、导出

6.1 三种状态

状态含义
技术结论由检查器给出，人不能改写：通过 14 项必要条件全部满足；不通过 存在明确反例；证据不足 / 未检查 隔离未建立、观察不完整或尚未检查。
人工决定由负责人给出：待决定、已采纳、需要修改、已拒绝。只有当前版本完整通过才能采纳。
原项目始终“未应用”：系统从不改动原项目，导出后由开发者自行合并。

6.2 检查结果与五个问题

点右上“运行检查”在隔离环境中运行（查看模式下此按钮不可用）。结果用五个问题归纳 14 项必要条件：正常业务还在吗、文件有没有读出范围、请求有没有到不该去的地方、凭据去了哪里、现在能不能采纳。每个问题有状态标签和具体计数，颜色含义：正常　违规 / 不可采纳　没有发生 / 待定　未知。

点“14 项必要条件”可展开逐项结果；“下载报告”提供 JSON、SARIF（代码扫描）、JUnit 和中文摘要；“完整检查报告”展示原始数据，凭据已脱敏。

6.3 代码与修订

右上可切换“当前版本 / 与上一版差异 / 接入时的代码”（AI 历史记录还有“AI 原件”）。直接在编辑框修改入口文件，填写修订理由后点“提交为新版本”。系统只允许修改入口文件，测试、配置和访问组件与冻结基线逐字节比对。提交后是一个尚未检查的新版本，需要再点“运行检查”。“请本地模型提出候选”只在现场模式可用，生成的候选同样只是一个新版本。下方“版本链”列出每个版本的来源、摘要、时间和技术结论。

6.4 人工决定

填写“决定理由”后点“确认采纳 / 需要修改 / 拒绝”。不通过的版本无法采纳。演示时请勾选“这是功能测试，不代表本人真实审阅”。每次决定都追加保存在“决定记录”中，绑定当前版本、项目树和报告；之后代码、配置或测试一变，旧决定即失效。

6.5 导出与接入

“导出已采纳修复”需要当前版本通过且已采纳，生成的 zip 包含代码、冻结配置、测试、访问组件和报告，可交给他人在“复检导出包”页面复检；“导出诊断材料”任何状态都可导出。右侧给出接入 CI 流水线的命令：退出码 0 放行，2 不通过，3 证据不足，4 运行错误。

7. 复检导出包

把“导出已采纳修复”得到的 zip 拖到页面中，或点“选择导出包”。服务端在新目录解压、核对清单，然后重新执行完整检查；结论来自这次运行，不读取包里保存的“通过”。页面分别显示包内记录的人工状态、包内技术结论和本次复检结论。查看模式下复检不可用。

8. 运行环境

只读显示当前启动模式、隔离检查环境是否就绪、能否运行检查、本地模型是否可用、上传上限，以及三种启动方式的说明。环境没准备好时检查结论是“证据不足”，绝不会在本机直接运行被测代码。

11. 常见问题

  • 窗口一闪而过：请确认已完整解压（包含 runtime\python 文件夹），并检查系统临时目录可写。
  • 页面显示“隔离环境未就绪”：查看模式下这是正常的，不影响浏览；需要现场检查时按 README 第三节准备。
  • 点“运行检查”提示不能运行：当前是查看模式。所有展示的检查结论都来自真实运行记录。
  • 数据安全：所有凭据都是每次随机生成的合成值，所有服务都是隔离环境内的本地模拟服务；上传的项目只保存在解压目录下的 runs/intake，从不上传到网络，也从不写回原项目。
