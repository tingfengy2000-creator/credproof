# v7 修订阶段诊断

这里是对 v7 第 7—9 次模型请求的结构化脱敏摘录，由保存的原始 wire
payload 派生，导出脚本本身不联系模型，也不执行候选。原始请求、响应和
完整工具轨迹仍保留在 5090 本地 artifact。

诊断结论：候选 2、程序自动验收的 `FAIL`、具体失败事实、必要测试结果、
`tool.py` 的实际读取结果和最新 `executor_state` 都进入了后续模型请求。因而
没有证据表明本轮是压缩器再次删除了这些材料。v7 的主要缺口是执行器在候选
失败后仍允许模型重复 `read_code`，而工作上下文没有明确把下一步收敛为“提交
实质不同的候选或停止”。

- `request-07-excerpt.json`：候选 2 被接受并自动验收为 FAIL 后的上下文、失败检查、工具 ID 和 usage。
- `request-08-excerpt.json`：模型收到候选 2 的完整源码读取及当前状态后的请求。
- `request-09-excerpt.json`：第二次相同读取及递增后的状态；随后第 10 次读取由原执行器的无进展保护拒绝。
- `diagnosis-index.json`：原始请求/响应 SHA-256、大小和字段省略说明。
- `../revision-stage-replay.json`：使用当前执行器代码对保存材料做的无模型协议检查。

保留字段包括实际 `call_id`、工具名称、参数、返回状态与 reason、候选摘要、
失败断言、pytest 摘要、对象状态和源码摘要。省略 stdout/stderr、原始审计行、
运行时凭据及本机绝对路径；候选源码另见上级 v7 公共证据目录。该诊断不计入
模型修复成功率。
