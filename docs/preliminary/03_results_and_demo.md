## 2. 分层计数：不混淆坏补丁与缺证据

所有方法使用相同 Gitleaks、合成规则与当前候选。主比较为 **10 个证据完整、范围相同的 fresh 案例**：4 个正确副本，6 个不符合修复契约的候选。另有 6 个证据异常案例，测试交付或汇总结果时的失效；这部分 A/B 是自建聚合器，不冒充规范 CI。

| 方法 | fresh 不合格候选被接受 | fresh 正确副本通过 | 证据异常仍被接受 | 全 16 例 UNKNOWN |
|---|---:|---:|---:|---:|
| A：只复扫 | 4/6（66.7%） | 4/4 | 6/6 | 0/16 |
| B：复扫＋语法＋受控功能 | 1/6（16.7%） | 4/4 | 5/6 | 1/16（6.25%） |
| C：完整验收 | 0/6 | 4/4 | 0/6 | 6/16（37.5%） |
| C-no-binding：五项检查但移除绑定 | 0/6 | 4/4 | 5/6 | 1/16（6.25%） |

分母按案例，不按重复次数。错误接受只要任一次 PASS 就计入；正确通过和稳定 UNKNOWN 要求三次一致。本轮无不稳定案例。C 的四个通过、六个失败、六个未知在三次重复中一致；剩余风险断言也全部通过。

**4/4 并不表示所有正确代码在任意条件下都能通过。** 证据异常组里有正确候选，因为必要证据缺失仍为 UNKNOWN。正确通过率分母限定为正常交付、完整范围的正例，另列 UNKNOWN 呈现保守性的代价。

### fresh：补丁本身

| 类别 | A | B | C | C-no-binding | 可得结论 |
|---|---|---|---|---|---|
| 标准正确、空白/注释变体、定义顺序变体、index 残留但副本正确（4例） | PASS | PASS | PASS | PASS | 并非只会拒绝；副本通过不覆盖 index 风险 |
| 原值换成普通常量，零告警却功能错误 | PASS | FAIL | FAIL | FAIL | B 已能识别，不是绑定独有能力 |
| 语法破坏、错误环境变量名（2例） | PASS | FAIL | FAIL | FAIL | 同样由合理 B 识别 |
| fallback 原值、另一文件残留（2例） | FAIL | FAIL | FAIL | FAIL | 成熟检测器本身能发现，不是我们的独有优势 |
| 额外改 notes.txt，受控功能仍正确 | PASS | PASS | FAIL | FAIL | 差异来自允许编辑约束；越过本次授权不等于一定恶意 |

### 证据异常：结论是否仍可用

| 情况 | A | B | C | C-no-binding | B-fresh：重采完整当前证据 |
|---|---|---|---|---|---|
| 实际范围遗漏 notes.txt | PASS | PASS | UNKNOWN | PASS | PASS，候选本身正确 |
| 没执行必要功能检查 | PASS | UNKNOWN | UNKNOWN | UNKNOWN | PASS，补足检查后正确 |
| 通过后把行为改坏，再交旧结果 | PASS | PASS | UNKNOWN | PASS | FAIL，重新测试也能发现 |
| 拼接另一对象、较窄范围、不同配置的扫描结果（3例） | PASS | PASS | UNKNOWN | PASS | PASS，副本正确，新证据已消除交付问题 |

B-fresh 在 fresh 组为 5/10 PASS、5/10 FAIL，其中越界改动仍 PASS；证据缺失组 2/2 PASS；交付组 3/4 PASS、1/4 FAIL。全部符合其独立的新输入预期。不能把旧证据的 UNKNOWN 标签套到已经重跑的正确结果上，诬称 B-fresh 错误接受。

消融在正常 fresh 组没有差异，在六个证据异常中有五例少了绑定就错误沿用通过。这只说明本实现对所构造的异常起作用；**不能由此推导它优于对相同提交、相同范围重新执行并约束允许修改的 CI。**

## 3. 开销与未证明的部分

每模式在同一正确两文件夹具上独立执行三次所需检查，轮换顺序，包含采证与验收。

| 方法 | N | 均值 ms | 最小—最大 ms | 样本方差 ms² |
|---|---:|---:|---:|---:|
| A | 3 | 334.885 | 329.045—343.003 | 52.604 |
| B | 3 | 334.675 | 333.218—337.427 | 5.688 |
| C | 3 | 333.329 | 327.450—343.709 | 81.287 |

观测 C−B = **−1.346 ms**。差异小于波动，不能宣称 C 更快，也不足以确定稳定的额外开销；只能说本机这个两文件夹具上均在约 0.33 秒量级。大仓库、不同机器与实际规则下成本尚未测量。

本轮支持：机制可执行、能接受计划内变化、能分开反例与缺证据、使错绑/旧证据失效、可从材料重跑，并保留原来源风险。尚未证明：未知模板泛化、真实秘密检测准确率、任意 Python 修复正确、抗恶意伪造、企业效果、超过成熟 CI 或稳定性能提升。

预期标签在第一次执行前登记，但 16 例全部参与开发；开发后澄清过分层及统计方式，协议已披露。只能称为机制开发试验，不能称预注册盲测。三次重复不是 48 个独立样本。下一轮应使用未参与修复开发的不同模板和独立断言，锁定后再测，保留新发现的问题与负结果。

## 4. 三分钟连续演示讲稿

运行 `python scripts/demo.py`，打开打印的 `public/story.json` 和各步报告。所有值均不能用于真实认证。演示终点刻意保留额外改动，故最后 recheck 返回 FAIL 是正确行为。页面尚未完成时展示终端和 JSON，不用 V2 假数据代替。

**0:00—0:25，问题。**

“我想解决的不是多检测一种密钥，而是修复后到底能不能说‘通过’。这个小程序要从指定环境变量读取凭据，变量缺失时明确失败，而且只允许改这一处赋值。所有值都是不能登录任何账户的合成标记。”

**0:25—1:05，零告警但不合格。**

“第一次我把原标记换成普通常量。Gitleaks 复扫确实零告警，这不是模拟输出。但注入两个不同环境值，程序没有按要求改变请求头，功能检查失败。零告警只回答没有发现这种标记，不能独自回答修复合格。普通扫描加充分测试也能发现这一例，我们不把它算成独有能力。”

**1:05—1:50，真正通过。**

“第二次只做约定的环境变量替换，保留其他内容。残留、语法、受控功能、范围和允许编辑都通过，证据还指向同一个副本、同一份规则和范围。系统现在给 PASS。原 index 仍有旧值，外部撤销没有验证。PASS 只针对这个副本，不表示泄露事件已经结束。”

**1:50—2:35，旧绿不能继续使用。**

“我在已通过的副本里额外改 notes.txt，再提交刚才的通过证据。系统重新读取对象，发现版本不一致，把旧证据标成 UNKNOWN。这时不是已经证明新代码坏了，而是旧材料不能回答新对象。再实际重跑：扫描和功能仍通过，但超出原先允许修改的范围，所以本次验收 FAIL。”

**2:35—3:00，价值与边界。**

“重点是让‘通过’带上适用条件，并能拿对应材料重新检查。首轮 16 个合成开发案例区分了正确修复、假修复和证据失效。规范 CI 也可以实现这些约束，我们做的是可复查的工程方法，不是新的安全理论。下一步是不同模板的独立评测。”

## 5. 五个容易被问到的问题

**这不就是扫描器加测试吗？** 底层确实复用扫描和测试。自行实现的是修复前冻结可执行契约、允许编辑与额外变化的区分、逐项证据适用性、三值判决、原来源与副本分开，以及重新执行的复检入口。“删掉秘密却破坏功能”用 B 就能发现，不能算独有创新。本轮增量很窄：允许编辑约束，以及拒绝拼接不适用的结果。

**为什么需要绑定版本和范围？** 一条通过只描述检查时读到的内容。检查 A 读版本一、B 读版本二，或者应查两文件却只查一个，不能共同支撑一次验收。绑定显式检查此前提。正常允许替换先通过验收，之后额外变化使旧结果过期；摘要帮助定位内容，不提供第三方信任。

**为什么不直接写一个 CI 脚本？** 可以。固定提交与范围、约束修改、完整运行义务、缺结果不放行的 CI 可实现等价保障，没有证明超过这样的 CI。CredProof 将本地未提交 worktree/index、受控副本和验收条件放入可复检流程，便于看懂“通过到哪里”。若只成立工程整合价值，就如实写，不上升为通用算法突破。

**报告如何复查，能证明到什么程度？** 报告显示对象、范围、每项状态和未覆盖风险；匹配材料交给 `recheck` 后重新读并执行，不依赖保存的 PASS。只有脱敏 JSON 没有原件/副本，不能完整复检。它支持“这个受控副本在这些条件下通过”的可重复结论，不证明云端撤销、历史清理或任意程序安全；同一操作者能改全部文件时，也没有抗伪造认证保证。

**哪些来自自己、开源和 AI？** Gitleaks 提供检测，Git 提供内容读取，Python 提供解析运行，验证思想也有研究先例。项目新增受限契约、绑定与三值规则、只读来源采集、报告/复检接口及受控案例与对照实验。代码、脚本和文稿使用 Codex 辅助编写、检查和整理，不能描述成全部手工原创；参赛者负责理解、需求/案例审查、复现和按赛事要求披露。Qwen 本轮没有接入或参与判决。开源归属见 [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md)。

## 6. 本轮停止点

关键机制验证成功，没有必要继续铺开平台；证据也不足以支撑普遍领先。下一步最有价值的是**冻结当前方法，做不同模板的独立留出评测，并与每次重新运行的合理基线比较**，再决定初赛创新性说明能写多大。单页前端随后只把真实证据讲清楚。
