# 答辩问答

**问：这和扫描器或 CI 有什么不同？**
答：扫描和 CI 仍然是本项目复用或共享的基础能力。本项目把受控触发得到的输出/文件/网络证据、候选补丁、必要业务检查和对象复检绑定在同一次验收中，并把模型权限限制在候选层。它不是声称替代扫描器或 CI。

**问：如果固定规则和人工也能处理，为什么有用？**
答：固定规则负责证据和判决，人工仍要提供授权范围和业务条件。模型的作用是阅读已授权代码、提出结构化候选并根据失败证据调整，减少从证据到修改之间的手工往返；当前没有测量节省了多少时间，所以不填写效率数字。

**问：你们真正新增了什么？**
答：三步都有代码和记录：受控证据反馈到候选（`agent_pilot/reliability.py`，h03）；程序实施写入边界和安全/业务联合验收（`agent_pilot/judge.py`、`credproof_safety/project.py`，python-dotenv 117/117 业务通过仍安全 FAIL）；对象绑定、导出和重新验收（`agent_pilot/web.py`、`agent_pilot/bundle.py`，导出三副本 PASS/FAIL/PASS）。

**问：模型犯错怎么办？**
答：模型不能直接批准修改。程序会拒绝越界、格式错误、仍有泄露或业务不满足的候选；必要证据不足显示 UNKNOWN。h03 的第一候选就是这样被拒绝的。

**问：目前支持什么？**
答：已登记、隔离、受控的 Python 工具，合成凭据和授权模拟服务；不支持任意仓库、多语言、真实云凭据撤销或任意网络目标。
