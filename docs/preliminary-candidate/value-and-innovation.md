# 价值与创新主张

## 让评委先看见真实任务

**谁使用：** 维护自有或获授权 Python/AI 工具及组件的开发者和安全人员。

**什么时候使用：** 凭据可能进入日志、异常返回等不应接收秘密的通道，或项目需要确认文件/网络边界；使用者要判断候选修复能否交付。

**使用者要完成：** 提供入口、授权范围、允许目录和服务、凭据变量、必要业务测试；确认问题、修改、检查业务、整理复查依据。系统负责受控触发、脱敏观察、候选补丁、固定验收和材料导出。

**交付什么：** 当前副本上的安全与业务结果、候选差异、对象摘要、检查时间、报告适用性和可再次运行的复检材料。

## 三个可核对的增量

| 困难 | 本项目机制 | 具体依据 | 边界 |
|---|---|---|---|
| 表面脱敏可能仍保留真实值 | 真实失败证据反馈给下一候选 | h03 首候选 FAIL、二候选 PASS；`agent_pilot/reliability.py` | 单例过程，不是普遍优势 |
| 业务绿不等于安全绿，模型也不能批准自己 | 程序限制修改并联合检查输出/文件/网络/pytest | python-dotenv 重新引入缺陷 117 项业务通过但安全 FAIL；`credproof_safety/project.py` | 已适配的隔离 Python 条件 |
| 绿色报告可能对应旧对象 | 导出对象、条件与复检入口，变化后重新执行 | `agent_pilot/web.py`、`agent_pilot/bundle.py`；导出消费者 PASS/FAIL/PASS | 哈希不是认证；历史缺件单列 |

## 已证明与待验证

已证明：当前资料助手和人工注入的 python-dotenv 副本可以执行三类安全观察、必要业务检查、对象绑定和无模型复检；固定、缺陷和无关导出副本能得到区分结果。待验证：人工时间收益、生产部署、跨机器和任意语言泛化。模型、Qwen-Agent、Ollama、pytest、隔离基础及上游组件不计为本项目原创算法。
