# 价值与创新主张

**密证 CredProof——面向 AI 工具的凭据泄露验证与受控修复系统**

**让 AI 提出修复，让程序决定是否接受，让开发者能够复查。**

## 为谁 在什么时刻

维护自有或授权 Python 工具、AI 工具及组件的开发者和安全人员，发现凭据可能进入日志、异常返回等禁止通道，需要确认问题并交付修复。Twine 的公开历史问题表明，配置解析失败也可能把敏感行带入控制台；本作品已受控复现该组件。

## 用户获得什么

一份候选补丁，以及触发条件、脱敏执行证据、安全与业务检查、对应副本和复检入口。人工仍需提供授权、接口适配、可信需求及必要条件，并决定是否应用补丁；模型不替人制定验收标准。

## 三项增量构成一个受约束修复方法

| 困难与已有处理 | 密证多做的一步 | 已有证据 |
|---|---|---|
| 有限规则没有处理某种代码结构；一次生成也可能留下真实值 | 模型提出候选，真实失败回执进入后续请求 | h01 补足项目启发式的参数日志遗漏；h03 首补丁失败后第二补丁通过。两例各自成立 |
| 模型怀疑或声称已修复，不能直接批准修改 | 程序依据当前证据授权，同时检查泄露、业务和修改边界 | h07 原代码保持；Twine 两份越界候选拒绝，第三份通过七项条件 |
| 保存的 PASS 可能对应旧副本 | 导出绑定材料，重读对象并重新验收 | 区分旧报告适用性、历史完整性和当前结果；对象变化回归及独立复检已有记录 |

## 证据强度与使用边界

冻结八例中 C 的问题修复 **4/4**、正常代码实际修改 **0/4**、完整任务 **6/8**；未完成仍保留。Twine 是**一个外部组件、七项条件、一次模型任务**，单列报告。它不替代官方升级，不代表泛化率。

本项目实现受限工具、证据门槛、裁判、完成控制和对象复检；模型、Agent 框架、推理服务及隔离基础来自开源。规范 CI 可承载类似检查；未证明优于所有扫描器或修复 Agent。本地部署是交付特点，不替代方法贡献。

**待验证的用户收益：**更容易理解修复依据和移交复查是目标；人工节时、总体效率、企业收益尚未测量。2—3 位开发者的探索性体验材料已准备，尚无真人结果。
