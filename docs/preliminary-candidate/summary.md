# 密证 CredProof——面向 AI 工具的凭据泄露验证与受控修复系统

## 摘要

本作品面向本地 AI 工具中无硬编码、但可能经日志、异常和嵌套返回外泄的运行时凭据，构建可追溯的诊断与修复原型。系统使用本地模型提出假设和补丁，由程序依据当前对象上的实际泄露证据授权修改，并在隔离环境中检查凭据通道、认证行为及异常分支。单页界面分别展示模型判断、程序确认、候选验收与任务完成状态，材料可导出并重新执行检查。同一冻结轮次的八个合成案例中，反馈 Agent 修复四个问题例，正常代码均未被实际修改；完整任务为六例，另两例因工具调用格式问题未完成。一个案例保存了失败补丁、真实反馈与再次修复的完整过程。作品的特点是把模型建议与执行权限、验收结论分开，为小型授权工具提供可检查的修复流程。当前结果限于受控 Python 轮廓和固定条件，不代表通用漏洞修复能力。

关键词：运行时凭据；本地智能体；受控修复；证据绑定；可复检材料

## 一页特点说明

### 从模型怀疑到可核对的运行证据

凭据由执行侧注入，源代码没有硬编码凭据。系统允许本地模拟认证使用凭据，同时检查返回值、异常、stdout、stderr 和日志。模型可提出触发假设，观察脱敏后的真实执行结果；公开 request_id、resource 或已脱敏日志不能单凭词面被判为凭据泄露。

### 把修改权限和结束条件交给固定程序

原始对象、规则与触发条件一致，且禁止通道上确有凭据值，才允许写入候选副本。模型生成的补丁需要通过 13 个固定条件，保留认证实参、调用次数及正常和异常功能。所有必要完成条件满足后由执行器结束任务；模型声称完成、正文工具标签或独立最终对象 PASS，都不能替代完整任务状态。

### 留下可以复查的失败与成果

代码差异、模型原文、工具调用、拒绝原因和最终对象一起呈现。h03 的第一份补丁没有移除真实值，程序拒绝后，第二份固定错误消息通过；错误解释仍保留。导出材料包含副本、契约及复检入口，复检重读当前对象并重新运行检查，旧报告是否适用与新对象是否通过分别报告。
