# 密证 CredProof：一页展示指南

**密证 CredProof——面向 AI 工具的凭据泄露验证与受控修复系统**

推荐顺序：**作品首页 → h01 有限修复增量 → h03 失败反馈 → h07 正常保留 → 对应对象复检与导出**。用 `python -m agent_pilot.launch --demo` 启动；页内导航为“系统机制／典型案例／验证工作区”，首页“探索典型案例”通向三张案例卡。三例均来自 `20260929t095000z-holdout8`，保持 **REPLAY** 标识。

## 一条操作路径，两种时长

| 实际区域／点击 | 60 秒 | 3 分钟 | 关键话 |
|---|---:|---:|---|
| 首页作品名、三个特点 →“探索典型案例” | 0—8 秒 | 0—20 秒 | 证据确认与授权，模型候选与反馈，程序验收，材料复检。 |
| H01「跨函数的日志泄露」→“程序确认”→展开“候选 1”差异 | 8—20 秒 | 20—65 秒 | A 未修好参数日志；C 保留认证并修好，说明本例增量。 |
| H03「看似脱敏，仍在泄露」→展开“候选 1”FAIL、“候选 2”PASS | 20—35 秒 | 65—120 秒 | 前缀变了但值仍在；反馈后换成固定信息。A 本例已成功。 |
| H07「正确脱敏，保持不变」→疑点、确认与空差异 | 35—47 秒 | 120—150 秒 | 合法认证不是泄露；无泄露依据，无补丁，原文件保留。 |
| “安全、功能与边界检查”→“重新验收”→“导出证据包” | 47—60 秒 | 150—180 秒 | 新复检不调用模型；旧报告适用性、材料完整性与新判决分开。 |

60 秒版展示复检入口或注明日期的已有记录；真实新复检须留等待。逐字稿见 [demo-script.md](demo-script.md)。[完整八例表](manuscript.md)中 A/B/C 修好问题 **3/4、1/4、4/4**，完整任务 **7/8、4/8、6/8**；后续复测不补原批成绩。
