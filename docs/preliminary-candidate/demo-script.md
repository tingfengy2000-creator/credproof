# 三分钟演示讲稿

本演示选用同一历史轮次 `20260929t095000z-holdout8` 的 h01、h03、h07。展示时保留“历史真实记录回放”标识，不把回放说成现场新推理；不使用后续 h05/h06 复测补齐历史任务成绩。若另做现场复检，明确它是对材料重新验收，并显示新输出时间与结论。

## 0 至 20 秒 说明问题

画面：作品首页、原代码和结果状态区域。

讲述：“这是密证。这里没有硬编码真实密钥，凭据只在隔离执行时注入，但工具仍可能把它写入日志或返回结果。我们的目标是让模型提出建议，让程序决定是否有依据修改，以及修复后能否验收。接下来展示同一冻结轮次中保存的真实执行记录。”

## 20 至 75 秒 h01 参数经过辅助函数进入日志

画面：选择 h01，展示 helper 参数日志、初始 logging 泄露证据、A 与 C 的最终对象状态和 C 差异；B 的完整结果见说明书测试表。

讲述：“凭据经参数传给辅助函数，既用于合法认证，也进入日志。初始诊断由程序实际执行，并将值脱敏后提供给各方法。A 是本项目的固定启发式，它没有覆盖这个参数日志路径；B 的候选只是空白变化，两者都未消除泄露。C 修改日志输出，保留原认证调用，候选通过十三个固定条件。这说明在这个结构上，模型提供了额外修复候选；它不是对成熟扫描器能力的结论。”

操作重点：先指原泄露回执，再指最终对象与验收内容，不先用绿色状态替代证据。不要展示真实账户或未脱敏运行值。

## 75 至 135 秒 h03 一份看似脱敏的失败补丁

画面：h03 的候选 1、FAIL 回执、候选 2、最终 PASS；下一请求中的完整工具反馈可在随包原始材料中复查。

讲述：“第一份补丁把 `credential=` 换成带脱敏标记的前缀，原值仍在后面，所以日志继续泄露。程序没有接受这个看似正确的补丁。失败回执真实进入模型下一请求；第二份补丁将动态异常详情换成固定错误消息，才通过验证。模型当时把原因解释为日志里还有 credential 单词，这个解释不对，我们保留原文，由实际代码和检查结果说话。固定程序 A 在这一例首份补丁就成功，因此它展示的是一次反馈修正过程，不是每个案例都优于规则。”

对应零基索引：h03/C-agent 的 `tool_trace[3]` 提交第一份、`[4]` FAIL；`model-06-request.json/messages[11]` 收到反馈；`[5]` 第二份、`[6]` PASS。最终对象是 candidate-2。

## 135 至 170 秒 h07 正常代码保留

画面：h07 的公开脱敏结构、模型最初疑点、PASS 观察、原文件与最终文件相同、完整任务状态。

讲述：“正常工具也可能含凭据变量。这里日志使用另建的脱敏结构，真实值只交给允许的认证接口。模型提出疑点，额外检查没有发现泄露，最终验证原文件。系统没有依据时不允许写候选，原代码保持不变。页面把模型怀疑、程序确认、对象验收和任务完成分别显示，避免把一句模型判断当作安全结论。”

## 170 至 180 秒 报告结果与边界

画面：同轮完整表、材料导出及重新验收入口。

讲述：“同轮八例中，C 修好四个问题例，完整任务是六例；两例工具格式失败仍保留为未完成。材料可以导出并重新检查。当前仅验证受控 Python 和固定条件，开源模型、框架及 AI 辅助开发的贡献均如实披露。”

## 演示准备和临场规则

- 启动页面不等于启动模型。提前确认选中的是固定历史记录；禁止临场自动重跑后挑选更好结果。
- 三个案例都来自该轮；正常例使用 h07，不替换成新复测 h05/h06。遇到加载失败，展示相应本地原始文件并说明状态，不伪造进度或成功回执。
- UI 截图、窗口标题、文件路径和元数据需做身份检查；原始证据不得改写。录屏的三分钟是本项目演示稿，不是官方初赛视频时长要求。
- 另做复检时使用新输出位置；若返回 UNKNOWN 或 FAIL，按实显示，不把历史 PASS 继续当作当前结果。
